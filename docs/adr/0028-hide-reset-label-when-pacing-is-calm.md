# ADR-0028: Приховування reset-тексту в menu bar, коли пейсинг спокійний

## Контекст

Menu-bar віджет завжди малював текст «час до ресету» (countdown) праворуч від пари барів
(5h зверху, 7d знизу). Коли обидва вікна йдуть спокійно — зелені або жовті — цей текст додає лише
візуального шуму: користувачу не треба стежити за часом, поки все гаразд. Countdown корисний саме
тоді, коли пейсинг вимагає уваги (бар помаранчевий чи червоний).

### Семантика кольору бару (джерело істини)

Кольори пейсинг-зазору градуює `PopupBarView.aheadColor` (AppKit-шар), спільна для popup і menu bar:

| Колір | Умова (fractions [0, 1]) | «спокійний»? |
|---|---|---|
| green | `pacing == .onPaceOrBehind` (`usage <= time`) | так |
| yellow | ahead && `usage < 1` && `(usage − time) < threshold` | так |
| orange | ahead && `usage < 1` && (`(usage − time) >= threshold` **або** ресет `≤ 20 хв`) | ні |
| red | `usage >= 1` | ні |

> `threshold = 0.16·(1 − timeFraction)` — динамічний поріг (ADR-0044). Історично тут стояло статичне
> `0.15`.

## Рішення

**Ховати reset-текст у штатному `.expanded`-режимі, коли ОБИДВА бари спокійні (зелений/жовтий);
показувати, щойно хоч один стане помаранчевим або червоним.**

Реалізація:

1. **Класифікація — чиста арифметика в `TokenPaceKit`.** `BarLayout.isCalm` дзеркалить пороги
   `aheadColor`: `pacing == .onPaceOrBehind || (usageFraction < 1 && (usageFraction − timeFraction)
   < 0.15)`. `aheadColor` живе в AppKit-шарі, який `TokenPaceKit` не імпортує (ADR-0009), тож пороги
   **свідомо дублюються** тут — це ціна тестованості без AppKit. Межа `< 0.15` строга, без epsilon
   (той самий контракт, що в `limitIndicator`).

2. **Рішення матеріалізується як `showReset: Bool` у `MenuBarMode.expanded`.** `reset` завжди
   обчислюється (як і раніше) — просто не малюється, коли `showReset == false`. Одне джерело істини,
   яке читають **і** рендер (`StatusItemView.drawBars`), **і** розрахунок ширини item
   (`barsBlockWidth`), — інакше label і `itemWidth` розсинхронізувалися б. `showReset` прямо
   тестується на рівні `MenuBarLayout` без AppKit.

3. **Idle (ADR-0027).** `BarView.isCalm` для idle-бару завжди `true` (його `layout` inert), тож у
   idle-стані рішення приймає лише 7-денний бар: `showReset = !seven.isCalm`.

4. **Тільки два головні вікна.** Враховуються `five_hour` і `seven_day`. Per-model 7-денні ліміти
   (`weekly_scoped`: Fable, Mythos, Opus, Sonnet) **не** впливають на menu-bar countdown — вони
   моделеспецифічні, у menu bar не малюються, і живуть лише в popup.

5. **Error-режим не чіпаємо.** У 30–60-хв stale-фазі (`.error` з барами, issue #12) countdown —
   частина діагностики, тому там `showReset` завжди `true`.

## Наслідки

- Менше шуму в menu barі у типовому «все гаразд» стані: лише два бари.
- Countdown повертається автоматично, щойно бодай одне з двох головних вікон переходить у
  помаранчеву/червону зону — тобто саме коли час до ресету стає релевантним.
- Ширина item динамічно стискається/розширюється разом із появою тексту (як і для інших режимів).
- Дублювання порогів `aheadColor` ↔ `BarLayout.isCalm` — обидва місця треба тримати в синхроні; це
  зафіксовано в doc-коментарях обох.

## Верифікація

`swift build && swift test` (513 тестів, включно з `BarLayout.isCalm` та `MenuBarLayout showReset`),
плюс запуск застосунку під трьома стабами (`TOKENPACE_STUB`):

- `screenshot` (5h green + 7d yellow) → текст прихований;
- `1` climbing (7d orange) → текст показаний;
- `idle` (синій 5h + 7d green) → текст прихований.
