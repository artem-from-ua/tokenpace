# ADR-0043: Уніфікований рядок «часу до ресету» в дропдауні + прибрання стану `.resetNow`

> **Частково витіснено [ADR-0091](0091-countdown-only-where-work-is-not-running.md).** Правило
> «зламаний `resets_at` → ⚠️ замість смужок» лишилось, але шлях до нього інший: **вичерпане** вікно
> зі зламаною датою більше не провалюється на шлях зі смужками, а дає окремий кейс
> `MenuBarMode.exhaustedUnknownReset` — **самотній ⚠️**; `ResetSelection` видалено разом із
> `selectReset`. Чинними лишаються `ResetClock.resetLine` і видалення `TimeToReset.resetNow`.

> Заміщає рішення **D5** [ADR-0030](0030-optimistic-reset-and-exact-timer.md) («`.resetNow` лишається
> safety-net»): кейс тепер **видалено**, а три його джерела розрулено явно (див. нижче).

## Контекст

Дропдаун показував «час до ресету» **по-різному** для різних лімітів:

- **Токен-вікна** (5h / 7d / per-model) — `resetText(_ row:)`: `20m at 05:30`, `3d on Monday`.
  Абсолютний час при `< 24 h`, день тижня при `≥ 24 h` (лише 7d), поріг — жорсткі 24 h.
- **Extra usage (credits)** — окрема гілка: лише відносне `6d`, без абсолютного дня/часу.

Issue #167 просило показувати абсолютний день/час для credits, коли ресет близько. У процесі обсяг
розширено мейнтейнером до **єдиного формату для всіх лімітів дропдауна** й до прибрання проміжного
стану `TimeToReset.resetNow`, який маскував **дві різні** ситуації однаковим фейковим `<1m`:

1. ресет **минув** (`remaining ≤ 0`) — мало б перекотитися на **наступний** ресет, а не показувати
   `<1m`;
2. `resets_at` **відсутній / не парситься** — це **помилка API**, і показувати її треба як помилку
   (⚠️), а не фейковим countdown.

Ресет credits детермінований — `00:00 UTC 1-го числа наступного місяця` (`CreditsPacing.monthEnd`),
тож абсолютну дату рахуємо локально; день тижня/час — у **місцевому** поясі.

## Рішення

### D1. Єдиний рядок `ResetClock.resetLine` для всього дропдауна

Одна чиста функція збирає **весь** рядок за таблицею зон (за фактичним залишком `remaining`), яку
використовують **і** токен-вікна, **і** credits:

| Залишок | Рядок | Приклад |
|---|---|---|
| `> 7 d` | `Nd` | `15d` |
| `6 d < r ≤ 7 d` | `Nd next <weekday>` | `7d next Monday` |
| `24 h < r ≤ 6 d` | `Nd on <weekday>` | `5d on Friday` |
| `r ≤ 24 h` | `Nh at <time>` / `Nm at <time>` | `20h at 03:00` |
| `r ≤ 0` | `nil` (shell → `resetting…`) | — |

- `N` — округлене число з наявного `relativeRounded` (не дублюємо арифметику).
- `<weekday>` — англійська назва (`Monday`), локаль-**незалежна**, у **місцевому** поясі.
- `<time>` — локальний `HH:MM`, локаль-**залежний** 12/24h.
- Пороги — за `remaining` (секунди); число `N` округлюється незалежно, тож на межах можливе легке
  розходження (напр. `6d 20h` → зона «next», `N` → `7d`) — прийнятно.
- `LimitRow`/`CreditsRow` тепер несуть **одне** поле `resetLine: String?` замість трьох
  (`resetRelative`/`resetAbsolute`/`resetWeekday`); shell лише падає на `resetting…` при `nil` (без
  префікса `resets in`). Прибрано `absoluteWithin`/`weekdayBeyond` (їх заміняє `resetLine`).

### D2. `remaining ≤ 0` → перекотити на наступний ресет (не `<1m`)

Перекочування вже реалізовано `ResetClock.optimisticReset` (ADR-0030 D2) + точним `resetTimer`. Щоб
усунути суб-секундну **гонку таймерів** (рендер від `ageTimer`/полл-тіка міг влучити між «межа
минула» і «таймер перекотив»), `optimisticReset` тепер застосовується **на кожному рендері**
(`AppDelegate.render`), а не лише при спрацюванні таймера. Тому `remaining ≤ 0` не досягає форматера
в нормальному потоці; на суто дегенеративному вводі `timeToReset` повертає безпечний `.relative("<1m")`
без окремого стану.

### D3. Зламаний `resets_at` активного вікна → помилка API (не `<1m` / не `resetting…`)

**Непорожній, але непарсабельний** `resets_at` на вікні з реальним використанням (`utilization > 0`)
— це малформований 200-body, тож обробляється як інша помилка API, **симетрично в menu bar і popup**:

- **menu bar** → **⚠️ замість пейсинг-барів** (той самий `.error`-режим і `exclamationmark.triangle`,
  що при staleness);
- **popup** → **лише червоний банер попередження** (`FailureReason.serverProblem`), **без** жодних
  рядків лімітів / credits / blocking-reset. На відміну від *health*-помилки (де застарілі рядки
  останнього **доброго** snapshot'у ще варто показати), тут малформований сам **поточний** snapshot,
  тож рендерити нема чого — та сама форма, що cold-start failure (порожні `rows` + банер).

Єдине джерело істини перевірки — `UsageSnapshot.hasBrokenActiveReset` (Kit), яким користуються **обидва**
layout'и: `MenuBarLayout.make` промотує в `.error`, `PopupLayout.make` виставляє `warning =
.serverProblem`. `MenuBarLayout.selectReset` додатково повертає `ResetSelection`
(`.hide` / `.show` / `.dataError(window)`) як defensive-guard.

**Що НЕ помилка:** (а) **порожня/`null`** дата — це boundary/synthesis-стан, а не малформоване
значення; (б) **нульове використання**; (в) **session-idle 5h** (ADR-0027: немає активної сесії — її
`resetsAt` порожній). Тобто помилку дає лише **непорожня непарсабельна** дата на **використаному**
вікні.

### D4. Кейс `TimeToReset.resetNow` видалено

`enum TimeToReset` тепер має лише `.absolute` / `.relative`. Три джерела старого `.resetNow` розрулені
вище: `remaining ≤ 0` → D2 (перекочування), зламаний `resets_at` → D3 (⚠️), error-branch fallback →
`reset: nil` (без countdown). Це **заміщає D5 ADR-0030**, чиє обґрунтування було суто «дешевий
safety-net», без продуктового сенсу.

## Наслідки

- Дропдаун показує один формат «часу до ресету» для кожного ліміту, включно з credits; префікса
  `resets in` немає ніде.
- Menu bar більше ніколи не показує фейковий `<1m` для минулого ресету (перекочується) чи для
  зламаної дати (⚠️, як справжня помилка).
- `TimeToReset` спростився до двох кейсів; `selectReset` явно розрізняє «сховати» / «показати» /
  «помилка даних».
- `optimisticReset` тепер render-time-інваріант, а не лише подія таймера — жодна гонка не породжує
  «reset now» плейсхолдер.

Верифікація — стуби дропдауна на різних залишках (credits `>7d`/`7d`/`5d`; токен `<24h`/`<1h`),
локальний день/час (не UTC 00:00), і menu-bar-стуб зі зламаним `resets_at` → ⚠️.
