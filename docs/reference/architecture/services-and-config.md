# Архітектура — сервіси, конфіг і Settings

Наскрізна картина — в [overview.md](overview.md). Тут — другий незалежний потік (статус сервісів
Claude), monitored-services конфіг, persistence/міграція, вікно Settings, архіватор логів і вікно
Troubleshoot.

## Статус сервісів Claude (#31)

Другий, незалежний від usage потік: на кожен `PollOutput`, коли `StatusCadence.isDue` (інтервал =
`max(5 хв, usage-інтервал)`), агент ходить у `status.claude.com/api/v2/summary.json`, декодує лише
`components[]`, зводить у логічні сервіси (`MonitoredServices`) і малює по рядку на монітований
компонент у popup — **лише** коли є проблема. Найсерйозніша проблема → одна крапка в menu bar.

## Вікно Troubleshoot (ADR-0020)

⌥-Option-гейтований пункт «Troubleshoot…» відкриває велике resizable-вікно `.normal`-рівня з
live-оновленням щополу: update interval + токен (read/expires) + сира відповідь usage API
(претіфікований JSON / payload помилки + HTTP-статус + timestamp). Діагностика тече чистим
`PollDiagnostics` пайплайном.

## Компоненти статусу сервісів

| Компонент | Відповідальність |
|---|---|
| **StatusHealth / StatusSummary** | Чисте ядро статусу сервісів (#31, #89; `TokenPaceKit`). `StatusSummary` парсить **лише** `components[]` — `incidents`/`status` навмисно НЕ декодуються (ADR-0013), тож «відомі виключення» не шумлять. `ServiceStatus` мапить сирий рядок → семантику (+ `severity`/`isProblem`). `StatusHealth` — колекція **логічних сервісів** `checks: [ServiceCheck]` (ADR-0024): кожен = `ServiceID` + `coworkEnabled` + `[ResolvedComponent]` + computed `status` = worst-of-N. `worstProblem` → найсерйозніший стан усіх увімкнених (сигнатура `ServiceStatus?` збережена). ADR-0013, ADR-0024 |
| **MonitoredServices** | Чистий Codable value-конфіг «які логічні сервіси моніторити» (#89, ADR-0024): `claudeCodeEnabled`/`webDesktopEnabled` + `WebDesktopMode` (`chatOnly`/`chatAndCowork`). `Claude API` завжди-on, не конфігурується. Forward-compat декод (невідомий режим → `.chatOnly`). `static default` = обидва on, `chatOnly` |
| **StatusClient** | HTTP-seam status-ендпоінта (`TokenPaceKit`), дзеркало `UsageClient`: чисті `buildRequest()` (обов'язковий `User-Agent`, без auth) / `decode(from:)` окремо від `fetch(transport:)`. Будь-який збій → `StatusFetchError` → shell робить `StatusHealth.unknown` — **не** ескалює usage 429-backoff. ADR-0013 |
| **StatusCadence** | Чистий seam ввічливої частоти (`TokenPaceKit`): `interval = max(floor, usageInterval)`. Без власного таймера — хантажиться з usage-tick. **Дві підлоги:** `floor` = 5 хв (все operational); `problemFloor` = 60 с (щойно є проблема). ADR-0013 |

## Persistence, міграція, Settings, архіватор

| Компонент | Відповідальність |
|---|---|
| **PersistedConfig** | Перший persistence-шар (#71, ADR-0023) — тонка `@MainActor`-обгортка над `UserDefaults.standard`. Фаза 1 почалась з `lastRunVersion`; шов розширено ключами: `calmMenuBarColors` (#105), `resetCountdownModeMenuBar` (#103), `showServiceStatusDot` (#31), `showExtraUsage` (default-ON, #144/#146 — **меню-барна** іконка ¤), видимість секцій дропдауна
(`modelLimitsVisibility` / `extraUsageVisibility`, raw `PopupSectionVisibility`, default `.nonCalm`,
#211/ADR-0072 — попап; перший мігрує з булевого `showModelSpecificLimits`), monitored services (#89), `automaticUpdateChecks` (#37), архіватор (`archiveEnabled`/`archiveDestination`/`lastArchiveSync`, #110), нотифікація «Back to work!» (`backToWorkEnabled` default-OFF / `notifyWindowStartMinute` / `notifyWindowEndMinute` / `notifySuppressDays` / внутрішній `backToWorkWasBlocked`, #160), журнал використання (`journalEnabled` default-OFF, #242/ADR-0067), геометрія вікна Settings (`settingsWindowFrame` = `[x,y,w,h]`, ADR-0069 — єдиний ключ *системного* штибу тут; свідомий виняток із межі 0023, бо значення треба **провалідувати до застосування**, а `setFrameAutosaveName` відновлює фрейм раніше, ніж це можливо). Рішення про міграцію — у чистому `MigrationPlan`. ADR-0023, 0069 |
| **MigrationPlan** | Чистий предикат on-launch міграції конфігу (#71, ADR-0023): `transition(stored:current:)` → `firstRun`/`unchanged`/`upgraded(from:to:)`. Порівняння — рядкова нерівність (каркас); повний SemVer-compare відкладено. Реюз у Фазі 2 |
| **LaunchAtLogin / LaunchAtLoginController** | Чисте ядро (#14): `Status` — framework-free дзеркало `SMAppService.Status` + предикати `shouldAttemptRegister` (opt-out на `.notRegistered` **і** `.notFound`, #69). Shell-glue над `SMAppService.mainApp`: `enable()`/`disable()`, `isAppBundle` (гейт opt-out auto-register лише на `.app`, #69). ADR-0012, ADR-0018 |
| **WorkAvailability / NotificationSchedule / SuppressDays / BackToWorkNotifier** | Нотифікація «Back to work!» (#160, ADR-0039). Чисте ядро в `TokenPaceKit`: `WorkAvailability.canWork(_:)` — предикат «чи можна працювати» (реюз `CreditsPacing.anyBaseLimitExhausted`+`isSpending`); `NotificationSchedule.isAllowed(...)` — quiet-hours гейт (AND вікна годин і suppress-дня; wrap через опівніч; **Правило A** — день прив'язаний до відкриття вікна) + `windowLengthMinutes`; `SuppressDays` — String-enum (never/friSat/satSun) з forward-compatible decode. Shell: `AppDelegate.apply` детектить фронт `blocked→unblocked` через персистований `PersistedConfig.backToWorkWasBlocked` (переживає рестарт і toggle off→on; трекінг завжди, постинг лише за enabled); `BackToWorkNotifier` — тонка `UNUserNotificationCenter`-обгортка (лениза авторизація при першому вмиканні, `.app`-only). ADR-0039 |
| **SettingsWindowController** | Вікно «Settings…» (#14, редизайн #131 ADR-0035, SwiftUI-переписання #168 ADR-0042): тонка single-instance hosting-обгортка — `NSWindow` (ширина 857 запінена, **висота resizable** ≥480 з дефолтом 732 — ADR-0069; `.floating`, zoom/miniaturize показані, зелена кнопка = вертикальний zoom через `windowWillUseStandardFrame`, full-screen вимкнено) з `NSHostingController(rootView: SettingsRootView(model:))`. **Публічний контракт `AppDelegate.openSettings` збережено дослівно** (10 callback + `archiveSummaryProvider` + `updateAvailability`/`updateArchiveStatus` + `show()`) — тепер computed-forward-иться в `SettingsModel`; `App.swift` zero-diff. `show()` кличе `model.syncFromConfig()` + `NSApp.activate`. Геометрія: пін ширини тримає `windowWillResize` (не size-межі — `NSHostingController` затирає їх під час першого layout-проходу); фрейм персистується ключем `settingsWindowFrame` і валідується чистим `WindowFrameValidator` (Kit) проти живих `NSScreen.visibleFrame`. ADR-0012, 0018, 0024, 0031, 0035, 0039, 0042, 0069 |
| **SettingsModel** | `@MainActor @Observable`-модель стану Settings (#168, ADR-0042), живе стільки, скільки контролер — **поза** SwiftUI-в'юхою. Тримає весь стан (mirror `PersistedConfig`), computed enablement (dev-build дизейбли launch/install-auto/back-to-work; radio-залежності), `syncFromConfig()` на кожен `show()`, persist-then-callback сеттери (спершу `PersistedConfig`, тоді `onXChange?`; `isSyncing`-guard від ретригера), фонові мутатори `updateAvailability`/`updateArchiveStatus` (мутують модель, не outlet → **eager-build прибрано**). Чиста логіка (reset-mode fold, minute-of-day↔Date) — static-функції, Kit-юніти. ADR-0042 |
| **SettingsRootView / *Pane / SettingsFieldSupport** | SwiftUI-в'юхи Settings (#168, ADR-0042): `SettingsRootView` — `NavigationSplitView { List(.sidebar) } detail:{}` (selection з `TOKENPACE_SETTINGS_SECTION`); `enum SettingsSection: Int` (0=About…4=Extra features) — джерело істини порядку/індексів; сайдбар згрупований у три `Section` (About / стандартні / Extra features) з роздільниками між ними. По одному `struct XxxPane: View` на панель, кожна `Form { Section }.formStyle(.grouped)` (**нуль констант**). `ExtraFeaturesPane` збирає кілька opt-in фіч секціями (Monitored services / Sessions backup / Session status / Usage history, #242). Мости в `SettingsFieldSupport`: `Binding<Date>`↔minute-of-day, `NSOpenPanel` (Choose…), `Picker(.menu)` (suppress). `AppearancePane` має кнопку копіювання конфіга (#257): `SettingsModel.appearanceConfigJSON()` → `AppearanceConfigExport` (Kit) → pretty-JSON у `NSPasteboard` (запис у буфер — у в'юсі, щоб модель лишалася без AppKit). Ключі йдуть **у порядку контролів панелі**, не за алфавітом — `Codable` порядку не тримає (невпорядкований keyed-контейнер), тож текст емітиться вручну; `Codable` лишається для зворотного round-trip. Свідомо лише Appearance-ключі (чиста презентація, без приватних даних) — повний дамп `PersistedConfig` чекає на per-key privacy-прохід (#256). Гліфи/тривалість checkmark-фідбеку — у Kit-типі `CopyFeedback`, спільному з копі-кнопкою Troubleshoot (різні тулкіти по обидва боки шва → константа, продубльована вручну, розійшлася б). Замінило `SettingsCard`/`SettingsRow`/`RoundedFieldBox`/`DividerView`/`FlippedView`/`SettingsSplitViewController`/`SettingsSidebarController` (усі видалені). ADR-0042 |
| **ArchiveSyncPlan / ArchiveCadence / LogArchiver** | Архіватор логів сесій (#110, ADR-0031). Чиста `filesToCopy(source:dest:)` — новий/змінений файл (mtime **або** розмір: дописаний `.jsonl` росте), **ніколи не повертає видалень** (accumulate-only). `ArchiveCadence` — фіксовані 24 год, маркер лише на успіху. `LogArchiver` (I/O-shell) дзеркалить allow-list тек `~/.claude/` (`projects/`/`file-history/`/`plans/`) — allow-list гарантує, що `.credentials.json`/токени фізично не потраплять в архів. Повертає `Summary`. ADR-0031 |
| **ByteSize** | Чистий форматер розміру (#110, `TokenPaceKit`): `humanReadable(_:)` → ціле + бінарна одиниця, **без десяткових/локалі** (навмисно не `ByteCountFormatter`, що локалізує). Для рядка стану архіву |
| **WindowFrameValidator / WindowFrameBox** | Чиста валідація збереженої геометрії вікна (ADR-0069, `TokenPaceKit`). `WindowFrameBox` — прямокутник у екранних координатах на простих `Double` (**без** CoreGraphics/AppKit, щоб Kit лишався придатним до Фази 2; конвертація `CGRect`↔box живе в shell). `resolve(stored:visibleFrames:defaultSize:minimumSize:)` → `.restore(box)` або `.centreDefault(size)`. Відкидає: відсутній фрейм, порожній список екранів (реальний стан під час реконфігурації дисплеїв), не-скінченні значення, розмір нижчий за мінімум, відсутність перетину з будь-яким екраном, видиму смугу тайтлбара < 120×44. Виправляє: клемп висоти під екран, зсув на екран-господар (найбільший перетин), нормалізація ширини до поточної константи. Межа свідома: «не дотягнутися мишею» невідновне, «завелике/трохи звисає» — відновне. 19 юнітів; це та перевірка, чия відсутність змусила ADR-0035 зняти persistence |
| **TroubleshootLayout / JSONHighlighter / TroubleshootWindowController** | Вікно Troubleshoot (ADR-0020). `TroubleshootLayout.make(...)` → рядки трьох секцій (update interval / токен / usage-API) вичерпним `switch` над `FetchDiagnostics.Outcome`; `prettyPrinted`/`timestampText`/`durationText`. `JSONHighlighter` — контекстний токенайзер JSON (не regex — пам'ятає контекст ключ↔value, не рве на `\"`). `TroubleshootWindowController` — resizable `.normal`-вікно (не `.floating` — конфлікт із fullscreen), read-only monospace `ReadOnlyTextView`, «Refresh now» → `forceRefresh`, copy body → `NSPasteboard` (з #257 — checkmark-фідбек за спільним `CopyFeedback`, як у копі-кнопки Appearance; `.momentaryPushIn`, бо `.momentaryChange` затирав би гліф на mouse-up). Live-оновлення щополу. ADR-0020 |
| **JournalRecord / PacingBucket / JournalGap / JournalReader / UsageGridAggregator / JournalFixture / UsageJournal** | Локальний журнал використання (#242, ADR-0067). **Kit (pure):** `JournalRecord` — тегований `usage`/`error`/`status`/`resume`/`unknown` із толерантним Codable (`decodeIfPresent`+дефолти, невідомий `kind`→`.unknown`); фабрики `usage(from:)`/`status(from:)`/`error(diagnostics:failure:)` маплять доменні типи в рядок (реюз `PacingModel`/`CreditsPacing`/`BlockingReset`/`ExtraUsageOnset`). `PacingBucket.of(_:)` — об'єктивний 5-way колір-бакет (blue/green/yellow/orange/red) з `BarLayout` без `CalmColorMode`, поріг синього завжди medium («режим контролфріка»). `gap` = `timePct·100−util` (усі ліміти + кредити з лімітом). `JournalGap.marker(...)` — resume-маркер при розриві > 2× очікуваного інтервалу. `JournalReader.parse(_:)` — стрім рядків, толерує зіпсований хвіст (`skipped`). `UsageGridAggregator.grid(...)` (крок 2 Insights, #244) — чистий агрегатор `[JournalRecord]`→сітка **днів × годин** (`UsageGrid`) для однієї метрики під одним фільтром; `now`/`timeZone` ін'єктуються (дефолт `.current` — сітка «коли я працюю» у локальному часі), рядки oldest→newest. Пілотна метрика `sampleDensity` (`dbg_sample_messages`) = к-сть успішних поллів у комірці `(день, година)` — діагностика щільності семплування. Фільтр `.fiveHour`/`.sevenDay` для density — свідомий **no-op** (кожен полл рахується однаково; параметр існує, щоб форма API вже підходила під util-метрики #245). Комірка `GridCell.gap` (накрита resume-інтервалом — «не дивилися», включно з годиною, що містить `t`) тримається **окремо** від `.value(0)` (0 семплів) — та сама чесність, що `ServiceStatus.unknown`/ADR-0027; gap перемагає семпл у тій же комірці. `.error`/`.status`/`.unknown` не рахуються. `JournalFixture.multiDay(...)` — генератор багатоденного ряду для верифікації. **Shell (I/O):** `UsageJournal` (actor) — non-blocking append під `flock(LOCK_EX)` (кілька інстансів у той самий файл), помісячне іменування `usage-journal[-dev]-YYYY-MM.jsonl` (release лише з `/Applications`), ніколи не кидає (лог+drop). Потік: `AppDelegate.apply`/`pollStatusIfDue` → `journalPoll`/status-seam (гейти `journalEnabled` + `.realNetwork`, запис off-actor) → `UsageJournal.append`. `plan`/`tier` (Keychain `subscriptionType`/`rateLimitTier`, не секрети) плинуть `TokenCredentials`→`TokenDiagnostics`→`output.diagnostics?.token`. **UI:** тумблер «Record usage history» у Settings → Extra features → Usage history (конфіг колектора; поряд read-only Location + Open in Finder); перегляд — окреме `InsightsWindowController` (стиль Settings, каркас-placeholder), відкривається з першого dropdown-пункту «Insights…». Dev-хуки `TOKENPACE_JOURNAL_FILE`/`TOKENPACE_GENERATE_JOURNAL`. ADR-0067 |
